## 背景与目标

- **背景**：日常工作经常需要查"X 月 X 日是否上班"、"两个日期之间有多少工作日"、"下次假期还有几天"。系统自带日历不显示中国调休补班，搜索引擎查询零散且不可批量。
- **目标**：纯前端一个 HTML，打开即用、含完整中国法定假期与调休数据；月历一眼看出哪天上班/哪天放假；快速做工作日数计算。
- **不做 (Out of Scope)**：
  - 不做用户系统、不做事项管理、不做日程提醒（这是日历工具不是日程工具）
  - 不做农历显示（首版不做，后续可加）
  - 不做多国假期（仅中国）
  - 不做后端、不做服务端数据持久化

## 用户场景与测试

### User Story 1 — 月历视图看法定假期与调休 (Priority: P0)
打开页面看到当月日历，法定假期红色显示，调休补班橙色显示，周末灰色，今天高亮。可以前后翻月份、跳回今天、切换年份。
- **为何 P0**：核心价值——一眼看出每天是工作还是休息
- **独立验收**：单独这一个 story 就能让用户判断某日是否上班
- **验收场景**：
  1. **Given** 打开页面，**When** 默认渲染，**Then** 显示当前月份的月历，2026 年端午（6月19日，周五）标为法定假期
  2. **Given** 在 2025 年 10 月，**When** 渲染，**Then** 10月1-8日标红（国庆中秋连休），9月28日（周日）/ 10月11日（周六）标橙（调休补班）
  3. **Given** 点击「下月」，**When** 翻到下一个月，**Then** 标题和单元格联动更新
  4. **Given** 点击「回到今天」，**When** 任意月份，**Then** 视图跳回 2026-06

### User Story 2 — 计算两日期之间的工作日数 (Priority: P0)
输入起止日期，返回区间内的工作日总数（不含周末/法定假，含调休补班）。
- **为何 P0**：第二高频需求——请假/排期/项目预估都要算
- **独立验收**：可独立成一个小卡片测
- **验收场景**：
  1. **Given** 起 2026-06-01、止 2026-06-30，**When** 计算，**Then** 工作日数 = 22（端午 6/19 放假 1 天，无调休补班，30 天 - 9 周末日 - 1 假 + 0 补 = 20，**留作实现期复核**，spec 仅描述行为）
  2. **Given** 起 > 止，**When** 计算，**Then** 提示"起始日期不能晚于结束日期"
  3. **Given** 区间内有调休补班的周末，**When** 计算，**Then** 该周末计入工作日

### User Story 3 — N 个工作日后的日期 (Priority: P1)
输入起始日期 + 工作日数 N（正负均可），返回目标日期。
- **为何 P1**：高频于"X 个工作日内回复"类场景
- **独立验收**：单卡片可测
- **验收场景**：
  1. **Given** 起 2026-06-08（周一）、N=5，**When** 计算，**Then** 结果 = 2026-06-15（周一，下周）
  2. **Given** N=0，**Then** 返回起始日本身（如起始即工作日）或下一个工作日（需在 design 中明确语义）
  3. **Given** N 为负数，**Then** 向前数 |N| 个工作日

### User Story 4 — 下一个法定假期倒计时 (Priority: P1)
显示离下一个法定假期（不含调休补班）还有多少天、是什么节日。
- **为何 P1**：增强体验、易实现
- **独立验收**：页面侧边小卡
- **验收场景**：
  1. **Given** 今日 2026-06-08，**When** 渲染，**Then** 显示"距离 端午节 还有 11 天（2026-06-19）"

### 边界条件
- **网络断开 / CDN 不可达**：jsDelivr 拉取失败时，应有 localStorage 缓存兜底；若首次访问且无缓存，应明确提示用户而不是默默没数据
- **跨年区间计算**：起 2025-12-20、止 2026-01-10，必须正确合并两个年度的假期数据
- **未来年度未发布数据**：访问 2027 年时，holiday-cn 仓库可能尚未发布数据，应展示"该年度法定假期数据尚未发布"提示而非崩溃
- **缓存过期 / 政策变更**：缓存策略需带 TTL，避免国务院补发公告后用户拿到过期数据
- **日期输入非法**：输入"2026-02-30"或纯文字，应被表单校验拦截

## 需求

### 功能需求
- **FR-001**：系统 MUST 在首次加载时从 `cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/{year}.json` 拉取当前年 + 上一年 + 下一年共 3 个年度的法定假期数据
- **FR-002**：系统 MUST 将拉取到的数据缓存到 `localStorage`，带时间戳；命中缓存且未过 TTL（7 天）则不重复请求
- **FR-003**：系统 MUST 渲染月历视图，对四类日期采用不同视觉样式：法定假（红）/ 调休补班（橙）/ 周末（灰）/ 今天（高亮边框）
- **FR-004**：系统 MUST 在每个特殊日期单元格 hover 时显示节日名称 tooltip
- **FR-005**：用户 MUST 能通过"上月 / 下月 / 回到今天"按钮切换月份
- **FR-006**：用户 MUST 能输入起止日期，得到区间内工作日数（含起止两端）
- **FR-007**：用户 MUST 能输入起始日 + N（整数），得到 N 个工作日后的日期
- **FR-008**：系统 MUST 在显著位置展示下一个法定假期的名称、日期、剩余天数
- **FR-009**：工作日判定规则 MUST 为：`(Mon-Fri 且不在 holiday list with isOffDay=true) OR (Sat/Sun 且在 holiday list with isOffDay=false)`
- **FR-010**：N 工作日计算的 N=0 语义 MUST 在 design 中固定（建议：返回起始日本身，无论起始日是否工作日；起始日若非工作日则返回它本身的日期值而非跳过）

### 关键实体
- **HolidayDay**：`{ name: 节日名, date: YYYY-MM-DD, isOffDay: bool }`——`isOffDay=true` 是放假、`false` 是调休补班
- **YearHolidayData**：`{ year, days: HolidayDay[], fetchedAt: timestamp }`

## 成功标准

### 可度量结果
- **SC-001**：浏览器双击 `index.html` 打开（或 `python -m http.server` 静态托管），无 console error
- **SC-002**：月历能正确显示 2024-2026 三年的所有调休安排（人工抽查 5 个已知调休日：2024-02-04、2024-09-14、2025-01-26、2025-10-11、2026-09-26 中实际发布的）
- **SC-003**：工作日数计算与"百度万年历"或同类权威工具结果一致（抽查 3 个跨假期区间）

- **SC-QA-001**：自测主流程（看月历 → 切月 → 算两日工作日 → 算 N 后 → 看倒计时）+ 错误流（起>止、断网、未来年度）全部通过
- **SC-QA-002**：纯前端无 build，跳过 lint（如果加 ESLint 则 0 error / 0 warning）
- **SC-QA-003**：核心纯函数（isWorkday / countWorkdays / addWorkdays）有 ≥1 单测；UI 部分手测
- **SC-QA-004**：浏览器（Chrome）手动跑通所有 4 个 User Story 验收场景
